# Roadmap

Goal: build the full v1 feature set, then ship Replybox to Google Play. Behavior is defined in `docs/PRODUCT_RULES.md`; items cite its rule IDs. The phase-by-phase reasoning and the PR-by-PR plan behind this are in `docs/PLAN.md`. Group related items into larger PRs; CI must pass. Tick items in the same PR that completes them, and date every decision that adds, moves, or drops one.

## Known bugs
<!-- Found and not fixed yet: what, where, and the rule it breaks. -->
- **A hidden message stays in the thread beside the words it was hiding** (CAP-8). `lib/capture/ingest.dart`, `_applyHistory`: when a redacted notification is later re-read with its real content (CAP-13), both rows are stored, so the thread shows a "hidden message" note above the message it hid. The text itself is no longer swallowed, and the system's marker string is still never stored. Both rows carry the notification's one post time and index 0, so their order is a tie the database breaks by id. Pinned green as BUG 2 in test/capture_ingest_test.dart. <!-- 21 September 2026, found while fixing the message-identity defect. -->
- **An app that starts sending `shortcutId` splits one thread in two** (CAP-3). `lib/capture/ingest.dart`, `_resolveKey`: the candidates that would let the app notice the change are stored on both conversation rows, and nothing reads them, so the same person appears twice in the inbox. CAP-3 says such an app is migrated rather than split silently. Pinned as BUG 4. <!-- 21 September 2026. -->
- **A queue sat undrained for about 13 seconds after a reboot; the cause is not known** (CAP-15, CAP-13). Immediately after a reboot, with the app in the foreground, two captured SMS stayed in `files/capture-queue.jsonl` for roughly 13 s and only reached the database after a force-stop and relaunch. It did not reproduce; this is one sighting. **No cause is recorded here, because none was established** — the Flutter engine pausing behind the post-reboot keyguard is a guess and nothing was measured that would confirm it. Written down so that a second sighting is recognised as a second sighting. <!-- 21 September 2026, device drill. Do not replace this with the guess; if it is ever reproduced, measure it. -->
- **`tool/spike.sh`'s redaction step is dead** (tooling, no rule). `cmd notification redact_otp_from_untrusted_listeners` now fails from the shell with `Package android does not belong to 2000`, so the step sets nothing while the run reads as though it had toggled something. It changes no result — OTP redaction is on by default at API 37 and was never observed off — but a script that reports an action it did not take is how a later run draws a wrong conclusion. <!-- 21 September 2026, device drill. `docs/research/spike.md` carries the matching correction; the script itself is untouched. -->
